# 08: Referential lists should be sorted alphabetically by default

**Blocked by:** None

**Status:** ready-for-agent
**Category:** bug

## Comments

> *This was generated by AI during triage.*

Reporter confirmed: lists are unsorted when online; default SQLite (binary) ordering is acceptable, no locale-aware collation needed.

## Agent Brief

**Category:** bug
**Summary:** Appellation, Producer and Meal lists are served sorted by name, but the client reads them from its local store in primary-key order, so the sort is lost everywhere the lists are shown.

**Current behavior:**
The server's list endpoints already `ORDER BY name`. The client list composables (appellations, producers, meals) sync that data into the local store (Dexie) and then read it back with a plain `toArray()`, which returns insertion/id order. Offline-created records (negative local ids) also land out of place. Result: autocompletes, filter dropdowns and management pages are not alphabetical. The meal-pairing composable reads meals the same way.

**Desired behavior:**
Every list of Appellations, Producers and Meals shown to the user is ordered by name ascending, using the same ordering as the server (plain binary/code-point comparison; no locale collation). This holds online and offline, and for records just created locally. Enforce it at the single point where the lists are read from the local store, not per view.

**Key interfaces:**
- The read path of the appellation, producer and meal composables (and the meal-pairing composable's meal reads): sort by `name` after reading from the local store
- Prefer one shared helper/ordered read so a new referential list can't forget it

**Acceptance criteria:**
- [ ] Test per list (Appellation, Producer, Meal): store seeded in non-alphabetical id order → composable returns name-ascending order
- [ ] Test: a record created locally (negative id) appears at its alphabetical position, not at the end
- [ ] Autocomplete options, management list pages and filter dropdowns show sorted data (covered by composable tests plus one view test)
- [ ] Order matches the server's `ORDER BY name` for ASCII and accented names (binary), so online/offline never reorder differently
- [ ] No change to server queries or API shape

**Out of scope:**
- Locale-aware / accent-insensitive collation (revisit with i18n)
- Sorting Wines (separate sort UI) or consumption history
