# 09: Sync-status page: detailed list of pending items on request

## Agent Brief

**Category:** enhancement
**Summary:** Let the user expand the sync-status page's pending counts into a per-item list of what is waiting to sync.

**Current behavior:**
The page shows one pending count per entity type (Wine, Consumption, Producer, Appellation, Meal, Meal Pairing) and a list of failed items with reason, Retry and Discard. Pending items are visible only as counts.

**Desired behavior:**
The summary counts remain the default, unchanged. A control on the page ("Show details") reveals a list of the pending (not failed) outbox items, and can be hidden again. Each row identifies the record in plain language (e.g. the wine's producer/appellation/millesime, the meal or producer name, the wine a consumption belongs to), the operation (create, edit, consumption, quantity adjustment, pairing add/remove), and when it was queued. Rows are grouped by entity type or ordered by queue time (agent's choice, stated in the tests). Failed items stay in their own section with Retry/Discard as today. The expanded/collapsed state need not persist across visits.

**Key interfaces:**
- The sync-status composable: expose pending items with a human label and operation, reusing the label logic already used for failed items
- The outbox item shape: needs a queued-at timestamp; if it isn't stored today, add it in a backward-compatible way (existing items without it render without a time, no migration failure)
- Sync-status view: toggle and list

**Acceptance criteria:**
- [x] Default render shows counts only; no pending list in the DOM until requested
- [x] Toggle reveals one row per pending item with label, operation and queued time; toggling again hides it
- [x] Items already in the outbox without a timestamp still render
- [x] Failed items are not duplicated in the pending list
- [x] Empty outbox: toggle hidden or shows an "Nothing pending" message
- [x] List updates live as items sync (same reactivity as the counts)
- [x] Component and composable tests

**Out of scope:**
- Per-item retry/discard for pending items (failed items only, as today)
- "Retry sync" and "Clear queue" actions (separate tickets 05, 06)
- Persisting the toggle state
