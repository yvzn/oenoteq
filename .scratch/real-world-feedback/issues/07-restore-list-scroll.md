# 07: Restore cellar list scroll position on back navigation

**Blocked by:** None

**Status:** done

## Agent Brief

**Category:** enhancement
**Summary:** Returning to the cellar list (browser/in-app back) from a Wine detail restores the previous scroll offset.

**Current behavior:**
Navigating back re-renders the list from the top, so the user loses their place in a long list.

**Desired behavior:**
After a back navigation (history pop) to the list, the scroll offset is restored once the list has rendered. Fresh navigations (new link click, filter/sort change) start at the top as today. Works with the list's filters and sort kept in the URL query.

**Key interfaces:**
- Router scroll behavior; the list loads asynchronously, so restoration must wait until results are rendered (or saved offset must be re-applied after load)

**Acceptance criteria:**
- [x] Test: scroll, open detail, go back → offset restored after results render
- [x] Test: forward navigation to the list from elsewhere starts at top
- [x] Changing filter/sort resets scroll to top
- [x] Pagination (planned: 10 per page, `?page=` in the URL, client-side slice) is not required here, but don't preclude it: the page lives in the URL, so back navigation already returns to the right page and this ticket only restores the scroll offset within it. Ideally schedule this ticket after pagination lands

**Out of scope:**
- Pagination itself
- Persisting scroll across full page reloads
