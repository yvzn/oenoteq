# 06: "Clear" button on the sync-status page

**Blocked by:** None

**Status:** done
**Category:** enhancement

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Escape hatch: let the user discard everything queued in the outbox when sync has gone wrong.

**Current behavior:**
Only individual failed items can be discarded (with a confirm dialog). Pending items cannot be removed, and a stuck outbox has no recovery short of clearing browser data.

**Desired behavior:**
A "Clear queue" action discards every outbox item (pending and failed) after a confirm dialog that states how many changes will be lost and that it can't be undone. After clearing, local data converges on server state through a pull so the UI doesn't keep showing never-synced local-only records. Counts and the header sync indicator reset.

**Key interfaces:**
- The outbox `discard` primitive generalised to all items
- A follow-up pull (`syncAll`-style) to drop local records whose create never reached the server
- Existing `ConfirmDialog`

**Acceptance criteria:**
- [x] Confirm dialog shows item count; cancel changes nothing
- [x] Confirm empties the outbox, counts show 0, header indicator hides
- [x] Local-only (negative id) records created by discarded items disappear after the follow-up pull; offline, that cleanup is deferred and tested/documented
- [x] Queued Consumption/quantity adjustments for discarded items are removed too, with the local quantity corrected or re-pulled
- [x] Component + unit tests

**Consent note (ADR 0010):**
Offline Mode only: the sync page and this action are hidden without Storage Consent. Revoking consent later reuses the same discard-all primitive behind its own flow (sync first, count and confirm if anything remains), so keep the primitive separate from this page's button and confirm dialog.

**Out of scope:**
- Selective multi-select discard
- Changing delete semantics (deletes stay online-only, ADR 0006)
