## Agent Brief

**Category:** enhancement
**Summary:** Add a page-level action on the sync-status page that triggers a sync attempt now.

**Current behavior:**
The page lists failed items with per-item Retry / Discard. Pending items only sync automatically (after a local write, or on reconnect). There is no way to say "try now".

**Desired behavior:**
A single "Retry sync" action on the page replays the whole outbox and refreshes local data, same as the reconnect path. While running it is disabled with a visible busy state; when finished the counts and failed list refresh. Offline: disabled, with a short explanation (or runs and fails gracefully; choose one and test it). Does not retry failed items implicitly unless that is what the per-item Retry does today; state the choice in the test.

**Key interfaces:**
- The sync entry point (the reconnect handler's `syncAll`) needs an exported, awaitable trigger
- The sync-status view and its composable

**Acceptance criteria:**
- [ ] Button visible on the page; click triggers a full push + pull
- [ ] Busy/disabled while in flight, no double-trigger
- [ ] Counts and failed list update after completion
- [ ] Behavior when offline is defined and tested
- [ ] Component test covers click, busy, completion

**Cellar list refresh:**
The offline wine list effort (`.scratch/offline-wine-list/issues/04`) defines one background refresh routine (push outbox, then pull) that this action should call, so "Retry sync" also refreshes the cellar list. Whichever ticket lands second wires it in.

**Consent note (ADR 0010):**
The sync page exists only in Offline Mode (Storage Consent granted). Without consent there is no outbox and the page is hidden, so this action needs no separate no-consent behavior. Write it against the sync entry point, not the local store directly, so it keeps working if the data gateway lands later.

**Out of scope:**
- Auto-retry/backoff policy changes
- Per-item retry/discard behavior (already exists)
