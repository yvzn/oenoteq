## Agent Brief

**Category:** enhancement
**Summary:** Within each Garde Status group, order wines by `garde_debut` (start year), following the status sort direction. The secondary key is not shown in the UI.

**Current behavior:**
Sorting by status orders wines by Garde Status rank only (`too_young`, `ready`, `past_peak`, `unassessed`), ties keep the existing deterministic fallback (producer/id order).

**Desired behavior:**
Ties within a status are ordered by `garde_debut`, in the same direction as the status sort (asc → earliest start first, desc → latest start first). Wines with no `garde_debut` sort after those with one, regardless of direction, so unset values never lead a group. Remaining ties fall back to the existing order. The UI shows no new column, indicator or control.

**Key interfaces:**
- The search results status sort (applied server-side after Garde Status is computed at read time, per CONTEXT.md)
- Sort direction param (`asc` / `desc`) already on `/search`; no API shape change

**Acceptance criteria:**
- [ ] Search test, asc: within one status, wines come back by ascending `garde_debut`
- [ ] Search test, desc: within one status, descending `garde_debut`
- [ ] Wines with null `garde_debut` last in their group in both directions
- [ ] Other sort columns unchanged
- [ ] `api.http` unchanged unless the request/response shape changes (it doesn't)

**Out of scope:**
- Offline/local search ordering (tracked with the offline wine list work)
- Any UI change
