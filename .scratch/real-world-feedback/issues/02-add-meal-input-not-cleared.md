## Agent Brief

**Category:** bug
**Summary:** In the Meal Pairing form, after creating a Meal through the autocomplete's "+create" option (which then auto-adds it as a pairing), the input keeps the typed text.

**Current behavior:**
The "+create" path creates the Meal, adds the pairing automatically, and shows create feedback, but the autocomplete input retains the text the user typed.

**Desired behavior:**
After a successful create followed by a successful automatic add, the input is empty and ready for the next meal. If the create or the add fails, the input keeps its text so the user can retry.

**Key interfaces:**
- The Meal Pairing view's create-and-add handler and the autocomplete component's input state

**Acceptance criteria:**
- [ ] Test: "+create" succeeds and pairing is added → input value is empty
- [ ] Test: create fails → input keeps its text and error shows
- [ ] Test: create succeeds but pairing add fails → input behavior matches existing error handling (state it in the test)
- [ ] Existing create feedback message still shows

**Out of scope:**
- The plain "pick existing meal" path
- Autocomplete behavior elsewhere
